ER Archive v0.16 — 로컬 VL 정밀 재처리 · HWP 일정 날짜 연결 수정

적용 방법 (기존 v0.15 설치 폴더에 덮어쓰기)
1. 기존 프로그램 실행 창에서 Ctrl+C로 종료합니다.
2. 05_backup.bat를 실행해 데이터를 백업합니다. STOPPED를 입력하고 백업 위치를 지정합니다.
3. ZIP을 풀고 er-archive 안의 파일·폴더를 기존 er-archive 안에 모두 덮어씁니다.
   기존 .venv / data / 모델 / 수집폴더는 삭제하지 마세요.
4. 팀원용은 03_start_team.bat, 본인 PC 전용은 02_start_local.bat를 실행합니다.
5. 브라우저에서 Ctrl+F5를 눌러 새 화면을 불러옵니다.
기존 Python·PaddleOCR를 재설치하지 않습니다. 이 ZIP에는 모델·가상환경·사용자 자료가 없습니다.

정밀 인식 사용법
- 서버가 실행되면 프로그램 폴더 아래 '정밀인식폴더'가 자동 생성됩니다.
- 재처리할 JPG/PNG/WebP 원본 이미지를 이 폴더 바로 아래에 넣으세요.
  파일당 15MB·4천만 화소 이하. 하위 폴더는 읽지 않습니다. 원본 파일은 이동·삭제하지 않습니다.
- 관리자 왼쪽 '정밀 인식 · 결과 검토' → '폴더 · 로컬 모델 상태'에서 경로를 바꿀 수 있습니다.
- 기존 자료 상세 → '본문 OCR 확인 · 교정' → 'VL 정밀 재처리 예약'으로 현재 페이지를 넣을 수도 있습니다.
- 복사 완료 후 15~30초 정도 지나면 대기열에 들어갑니다. 인식 시간은 별도로 걸립니다.
- 동일 이미지 바이트는 이름을 바꾸어 넣어도 정밀 대기열에 한 번만 등록합니다.
  이미지를 재저장·압축하면 다른 파일로 인식할 수 있습니다.
- 기존 자료와 같은 이미지면 기존 본문을 비교용으로 보존합니다.
  새 이미지에는 PP-OCRv5 1차 인식을 한 뒤 VL을 실행합니다.
- 상태: 대기 → 정밀 인식 중 → 완료·확인 필요 / 실패.
  실패 시 오류 확인 후 '다시 시도'. 서버가 중단되면 재실행 시 작업을 다시 시작합니다.
- 브라우저를 닫아도 서버 PC와 프로그램이 켜져 있으면 계속 처리합니다.
- 완료 자료의 '원본·결과 비교'에서 현재 본문 / VL 결과 / 원본 이미지를 비교하세요.
  VL 결과를 직접 교정한 뒤 '확인한 본문 적용', 또는 '기존 본문 유지'를 누릅니다.
- 기존 자료의 제목·발행처·호수·분류·게시 상태는 바꾸지 않습니다.
  본문은 관리자 적용 전까지 자동으로 덮어쓰지 않으며 적용 전 본문과 VL 원결과를 보관합니다.
- 아직 등록되지 않은 이미지는 적용 시 위치를 선택합니다.
  · 홍보물: 일괄 처리에 한 장짜리 묶음으로 등록 → 분류 확인 후 게시.
  · 일정만 추출: 일정 검토 후보만 생성. 홍보물 자료실에는 올리지 않음.
- HWP는 정밀인식폴더가 아니라 기존 일정자료수집폴더에 넣으세요.
  이미지로만 된 HWP, HWPX, DRM·암호·배포용 HWP는 지원하지 않습니다.

로컬 VL 모델 연결 (앞서 설치·시험한 환경을 그대로 사용)
기본 Python: %USERPROFILE%\PaddleOCR-VL\.venv\Scripts\python.exe
기본 레이아웃: %USERPROFILE%\.paddlex\official_models\PP-DocLayoutV3
기본 VL 모델: %USERPROFILE%\.paddlex\official_models\PaddleOCR-VL-1.6
  PaddleOCR-VL-1.6-0.9B 이름의 캐시 폴더도 자동 확인합니다.
07_check_vl.bat 또는 관리자 화면에서 경로·누락 파일을 확인하세요.
모델 위치가 다르면 실행 BAT의 Python 실행 줄보다 앞에 아래처럼 추가할 수 있습니다.
set "PADDLE_VL_PYTHON=C:\실제경로\.venv\Scripts\python.exe"
set "PADDLE_VL_LAYOUT=C:\실제경로\PP-DocLayoutV3"
set "PADDLE_VL_MODEL=C:\실제경로\PaddleOCR-VL-1.6"
필요하면 set "PADDLE_VL_HOME=C:\실제경로\PaddleOCR-VL" 도 지정하세요.

CPU·사내망 동작
- 로컬 CPU 실행만 사용합니다. 외부 API 호출이나 자동 모델 다운로드를 하지 않습니다.
- 정밀 인식 하위 프로세스는 외부 연결을 차단하며 모델이 없으면 실패 사유를 표시합니다.
- JSON 결과만 저장하여 이전 PingFang 글꼴 다운로드 오류 경로를 사용하지 않습니다.
- PP-OCRv5와 VL은 동시에 추론하지 않습니다. VL 실행 전 v5 모델 프로세스를 종료합니다.
- VL 한 장 처리 후 프로세스를 종료해 메모리를 반환합니다. 다음 VL 작업은 모델을 다시 읽습니다.
- 홍보물 한 장 → 일정자료 한 건 → 정밀 인식 한 장 순으로 대기 작업을 처리합니다.
  VL이 실행되는 동안 다른 OCR은 기다리지만 열람·검색은 계속 사용할 수 있습니다.
- '자동 수집·대기 작업 처리'를 끄면 새 수집과 다음 VL 작업을 멈춥니다.
  이미 진행 중인 한 장은 완료 후 멈춥니다. 한 장 최대 30분 후 실패 처리됩니다.
- Windows 실제 모델 추론 시간·메모리는 이 개발 환경에서 재측정하지 못했습니다.
  처음에는 한두 장으로 확인하세요. 이전 비교처럼 VL도 제목·고유명사를 놓칠 수 있습니다.

HWP 일정 수정과 기존 후보 정리
- HWP 5의 실제 셀 행·열·병합 정보를 읽습니다.
- 달력의 연속 날짜 행과 바로 아래 같은 열의 행사 셀을 연결합니다.
  같은 셀 안의 날짜·행사도 처리합니다. 날짜가 없는 셀·모호한 병합 셀에 날짜를 임의로 붙이지 않습니다.
- 구조를 확인할 수 없는 표는 추정으로 옆 주 날짜를 채우지 않습니다.
  출처 본문에서 '[날짜 미연결]'로 남은 항목은 관리자가 원본을 확인해야 합니다.
- 한 문장에 여러 날짜·행사가 있으면 쉼표/세미콜론 등으로 분리하고 각 날짜의 행사만 연결합니다.
- '27일'처럼 월이 없으면 명시된 주체와 파일명/발행일 근거가 있을 때만 월을 추정하고 경고를 붙입니다.
- '전노대', '특별산안보', '마음돌봄 수련회' 등 이번 자료의 표기를 보완했습니다.
- 업데이트 후 백그라운드 일정 검사에서 보관 HWP 원본을 다시 읽어 셀 구조를 복원합니다.
- 손대지 않은 기존 자동 후보는 재계산합니다. 사라진 오인식 후보는 삭제 대신 보관 상태로 옮겨 검토 목록에서 숨깁니다.
- 직접 수정한 후보, 확정·게시 일정, 제외한 일정은 그대로 보존합니다.
  관리자가 처리한 날짜에는 같은 출처의 새 후보를 다시 만들지 않습니다.
- 기존에 잘못된 날짜를 이미 직접 수정하거나 확정한 경우에는 자동으로 바꾸지 않으므로 직접 확인해 주세요.
- 메뉴 '일정 확인 · 검토'에서 잠시 후 새로고침하세요. 원본을 못 읽으면 오류를 표시하고 그 자료의 기존 후보를 유지합니다.
- HWP 원본 파일명과 다운로드 링크는 유지합니다. 추출된 일정은 계속 관리자 확인 후 게시합니다.
