## v0.11 변경사항

- **전체 바로 게시**: 임시등록을 거치지 않고 현재 수정한 분류와 페이지 순서로 바로 게시합니다. 사전 확인 체크를 하지 않은 경우 게시 버튼에서 확인창이 열립니다. 제목을 인식하지 못한 자료는 `제목 미상`으로 게시되며 나중에 수정할 수 있습니다. 임시등록은 계속 비공개입니다.
- **묶음 드래그**: 페이지의 `끌어서 이동` 부분을 잡아 카드 앞/뒤로 놓으면 순서가 바뀝니다. 다른 묶음의 카드 위에 놓으면 해당 위치로 이동합니다. 묶음 빈 공간은 맨 뒤에 추가하고, 하단 분리 영역은 새 묶음을 만듭니다. 드롭다운과 화살표도 계속 사용할 수 있습니다.
- **카카오톡 파일명 수정**: 긴 날짜·시간 숫자는 유지하고 `_01` 같은 짧은 페이지 접미사만 비교해 앞뒷장 연결 오류를 수정했습니다.
- **상단 디자인 비교**: 상단 약 23%의 색상 배치와 형태를 축소 비교합니다. 단색이나 빈 종이만 비슷한 경우는 제외합니다. 발행처·제목·발행일·호수가 충돌하면 합치지 않으며, 여러 묶음과 비슷하면 별도로 남깁니다.
- **기존 인식 결과 다시 묶기**: 일괄 처리 → 묶음 확인 → `상단 디자인 포함 묶음 다시 제안`. OCR을 다시 실행하지 않습니다. 현재 묶음과 분류 수정이 초기화되므로 확인창을 읽고 진행하세요. 이미 게시/임시등록한 자료는 기존 상세 화면의 병합 기능을 사용합니다.

상단 디자인 유사도는 같은 홍보물임을 보장하지 않습니다. 같은 양식의 다른 호수인데 호수가 인식되지 않은 경우 잘못 묶일 수 있고, 앞뒷장의 상단이 다르면 디자인으로 연결하지 못할 수 있습니다. 자동 제안을 확인한 후 게시하세요. 새로운 모델이나 외부 서비스 설치는 필요 없습니다.

## 기존 사용자의 업데이트

이번 ZIP은 업데이트용이며 Windows 의존성 패키지와 OCR 모델을 포함하지 않습니다. 기존에 설치한 프로그램 폴더에 덮어써서 사용하세요.

`UPDATE_업데이트안내.txt`를 따라 서버 종료 → 백업 → 기존 폴더에 덮어쓰기 → `06_check_paddle.bat` → 기존 실행 파일 실행 → 브라우저 Ctrl+F5 순서로 진행하세요. 기존 `.venv`와 데이터 폴더는 유지합니다. 초기 설치를 재실행하지 않습니다.

## PaddleOCR 연결

이번 버전은 별도로 설치한 PaddleOCR Python 환경과 로컬 모델을 사용합니다. 사용자가 직접 시험에 성공한 CPU 설정(enable_mkldnn=False)을 적용했습니다.

- 실행 환경: `%USERPROFILE%\PaddleOCR\.venv\Scripts\python.exe`
- 탐지 모델: `%USERPROFILE%\PaddleOCR\models\det` (PP-OCRv5_server_det)
- 한국어 인식 모델: `%USERPROFILE%\PaddleOCR\models\rec` (korean_PP-OCRv5_mobile_rec)
- 각 모델 폴더: inference.yml, inference.json, inference.pdiparams
- 다른 위치라면 실행 전에 `PADDLE_OCR_HOME` 환경변수로 PaddleOCR 폴더를 지정합니다. Python 경로만 다르면 `PADDLE_OCR_PYTHON`을 지정합니다.
- `06_check_paddle.bat`는 경로와 파일 존재 여부를 검사합니다. Ready가 실제 추론 성공을 의미하지는 않습니다.
- PaddleOCR/PaddlePaddle 설치 패키지와 Paddle 모델은 이 ZIP에 포함하지 않았습니다. 현재 PC의 설치를 재사용합니다. 새 PC에서는 해당 환경을 먼저 준비해야 합니다.
- 모델 서버 연결 확인을 생략하고 로컬 모델을 지정합니다. 결과 그림을 만들지 않고 JSON만 저장하므로 결과 시각화용 폰트 다운로드가 없습니다. 외부 OCR API로 이미지를 전송하지 않습니다.
- 한 장씩 순차 처리하며 장당 실행 한도는 5분입니다. 첫 작업 때 모델을 불러오고 이후 작업에서는 같은 프로세스와 모델을 재사용합니다. 첫 장에는 초기 로딩 시간이 포함됩니다. 서버를 종료하면 모델 메모리도 해제됩니다.
- 실행 실패 시 원본 등록과 수동 입력은 가능합니다. 실패 상태를 표시하며 Tesseract로 몰래 전환하지 않습니다. 이전 Tesseract 코드·모델은 호환 기록용으로 남아 있으나 기본 경로에서는 실행하지 않습니다.

## 화면과 자료 관리

팀원 화면은 집행부 / 제조직 / 그룹사 / 기타의 가로로 나란한 세로 4구역입니다. 작은 화면에서는 가로 스크롤합니다. 각 구역은 최신 발행일순이며 날짜·발행처·제목·호수를 표시합니다. 목록 미리보기와 주제는 없습니다.

관리자 카드에서는 발행처를 가장 크게 표시하고 제목 옆에 호수를 붙입니다. 자료 유형은 홍보물 / 교섭소식 / 성명서 드롭다운입니다. 기존의 다른 유형은 저장 전에 새 유형을 선택해야 합니다. 주제 입력과 태그 표시는 제거했으며 기존 데이터는 보존합니다.

이미지 한 파일은 한 페이지입니다. 여러 홍보물을 함께 업로드할 수 있습니다. 등록 방식에서 자동 묶음 또는 한 홍보물을 선택하세요. JPEG/PNG/WebP, 장당 15MB, 최대 20장·총 60MB입니다. 임시자료는 관리자만 볼 수 있으며 확정·게시 후 팀원에게 공개됩니다.

제목·발행처 자동분류는 PaddleOCR 인식 결과와 발행처 명부 및 알려진 홍보물 제목을 대조합니다. 상단·하단에서 발행처를 찾고 제목의 분리된 글자를 연결해 대조합니다. 임의 추측은 하지 않으며 확인되지 않은 제목/발행처는 관리자가 입력합니다. 날짜와 호수도 원본과 확인하세요.

## 수집폴더 자동 수집

프로그램을 시작하면 프로그램 폴더 안에 `수집폴더`가 만들어집니다. 관리자 화면의 **수집폴더 설정**에서 실제 경로를 확인하고 변경할 수 있습니다. 기존 공용폴더를 쓰려면 서버 PC의 실행 계정이 읽을 수 있는 전체 경로를 입력합니다. 예: `C:\홍보물수집` 또는 `\\서버\공유\수집`. 지정할 폴더는 먼저 만들어 두세요.

- 수집폴더에 JPG/PNG/WebP 이미지를 바로 넣습니다. 하위 폴더는 읽지 않습니다.
- 5초 간격으로 확인하고, 파일 크기·수정시간 변화가 15초 동안 없으면 읽습니다. 복사 중 다시 변경되면 기다립니다.
- 원본 파일은 옮기거나 삭제하지 않고 자료실 데이터 폴더로 복사합니다.
- 파일 내용의 SHA-256 해시로 중복 여부를 확인합니다. 파일명 변경·서버 재시작·기존 브라우저 업로드에도 같은 파일을 반복 등록하지 않습니다.
- 중복 이력은 자료를 삭제해도 유지됩니다. 삭제한 파일을 같은 내용으로 다시 넣어도 자동 재등록하지 않습니다. 이미지를 재압축하거나 편집하면 다른 파일로 취급할 수 있습니다.
- 장당 15MB, 작업당 20장·총 60MB 단위로 나눠 대기열에 넣습니다. 여러 작업으로 나뉜 경우 묶음 제안도 작업별로 이뤄집니다.
- **일괄 처리·진행 확인 → 묶음 확인**에서 분류를 수정하고 게시합니다. 자동 게시하지 않습니다.
- 수집폴더 설정에서 켜기/끄기, 최근 수집 및 중복 제외 수, 잘못된 파일과 연결 오류를 확인합니다.
- 프로그램이 켜져 있으면 브라우저를 닫아도 수집합니다. 서버나 PC가 꺼진 동안은 중단되고 다음 실행 때 남은 파일을 확인합니다.

## 팀원 열람창

열람창이 화면 대부분을 사용하며, 기본은 **한 페이지 전체 맞춤**입니다. 전체 지면이 화면 안에 들어오므로 첫 화면에서 아래로 스크롤할 필요가 없습니다. 여러 페이지는 이전/다음으로 이동합니다.

발행처·발행일·호수·유형은 상단에 모았습니다. 오른쪽 정보 영역은 기본적으로 숨겼으며 **자료 정보**를 눌렀을 때만 겹쳐 열립니다. **＋/−**로 전체 맞춤 기준 최대 4배까지 확대·축소하고, **전체 맞춤**으로 돌아옵니다. 확대 상태에서는 스크롤로 상세 부분을 볼 수 있습니다. 다음 페이지로 넘어가면 전체 맞춤으로 초기화됩니다.

## 일괄 처리 사용법

1. 관리자 → 홍보물 등록 → 여러 홍보물·자동 묶음 제안 → 이미지 선택 → 대기열에 추가.
2. 업로드 완료 후 다른 화면을 사용하거나 브라우저를 닫아도 서버가 켜져 있으면 순차 처리합니다.
3. 왼쪽 일괄 처리·진행 확인에서 완료 장수/전체 장수와 실패 장수를 확인합니다. 화면은 3초마다 갱신됩니다.
4. 처리 완료 → 묶음 확인. 각 묶음의 제목·호수·발행처·날짜·유형·자료 분류를 수정합니다.
5. 페이지 아래 이동 메뉴로 다른 묶음에 합치거나 새 묶음으로 분리합니다. 화살표로 순서를 바꿉니다. 이미지를 누르면 원본을 엽니다.
6. 검토 내용 저장: 나중에 이어서 검토합니다. 전체 임시등록: 기존 상세 화면에서 본문을 교정합니다. 전체 바로 게시: 확인 후 팀원에게 공개합니다. 임시등록을 먼저 할 필요가 없습니다.

발행처와 호수가 일치하면 묶음을 제안합니다. 파일명 a.jpg/a_01.jpg처럼 이어져도 묶음 후보로 만듭니다. 발행처·제목·날짜·호수가 서로 충돌하면 자동으로 합치지 않습니다. 명확한 근거가 없는 페이지는 별도로 남깁니다. 파일명에 의한 묶음은 정확한 문서 경계라는 보장이 없으므로 반드시 확인하세요. 페이지 번호 자체를 해석하는 기능은 이번 버전에 포함하지 않았습니다.

실패한 페이지도 원본과 오류 상태가 남습니다. 실패한 페이지만 재인식할 수 있지만 묶음 제안은 새로 생성되어 검토 중 수정한 묶음 정보는 초기화됩니다. 실패한 페이지를 포함해 임시등록한 뒤 상세 화면에서 직접 본문을 입력할 수도 있습니다.

대기열·페이지별 완료 결과·저장한 검토 내용은 데이터 폴더에 보존됩니다. 서버 재시작 시 완료된 페이지는 건너뛰고 중단된 페이지부터 다시 처리합니다. 저장 버튼을 누르지 않은 화면 편집 내용은 보존되지 않습니다. 서버 종료·PC 절전 중에는 처리하지 않습니다. 자동 실행은 포함하지 않았습니다.

속도 개선은 모델 반복 로딩과 자동분류 재확인 시 중복 OCR을 없애는 방식입니다. 해상도·모델·MKLDNN 설정을 유지하여 본문 인식 품질을 임의로 낮추지 않았습니다. 본문 추론 자체의 시간이 줄어든다고 보장하지 않습니다. 첫 장과 두 번째 장의 처리 시간을 묶음 확인 화면에서 비교할 수 있습니다. 실행 중 모델이 메모리에 상주합니다.

## 본문 재인식과 검색

기존 자료 상세 → 페이지별 OCR 확인·재인식 → 이 페이지 다시 인식 → 후보 검토/교정 → 본문 입력란에 적용 → 상세 상단 저장 순서입니다. 재인식 자체로 저장된 본문은 변경되지 않습니다. 최초 보관 본문과 변경 전 이력은 유지합니다. 업데이트 전에 수정한 본문은 최초 OCR이 아니라 업데이트 당시 스냅샷일 수 있습니다.

확인 문구를 누르면 원본의 해당 부분이 확대됩니다. PaddleOCR은 문구/줄 단위 신뢰도를 반환하므로 한 글자만 잘못 읽어도 높은 신뢰도가 나올 수 있습니다. 신뢰도는 실제 정답률이 아닙니다. 숫자·금액·인명은 자동 교정하지 않습니다.

기본은 PaddleOCR 읽기 순서를 유지합니다. 2단 옵션은 상단과 하단을 유지하고 중간 본문을 좌우 순서로 정리합니다. 본문이 중앙을 가로지르면 원래 순서를 유지합니다. 복잡한 다단 지면은 직접 확인하세요.

검색은 저장된 교정 본문을 사용하며 띄어쓰기와 일부 약칭 차이를 처리합니다. 유사어 포함은 4~16자 한글 검색어의 한 글자 차이를 허용하는 선택 옵션이며 기본은 꺼져 있습니다.

## 실행과 백업

기존 데이터 기본 위치: `%LOCALAPPDATA%\ERArchive\data`. 반드시 같은 Windows 계정으로 실행하세요.

- `02_start_local.bat`: 관리자 PC에서 http://127.0.0.1:8080 접속
- `03_start_team.bat`: 팀원이 http://관리자PC사내IP:8080 접속
- `05_backup.bat`: 서버 종료 후 백업. 공용폴더는 백업 보관·패키지 전달에 사용합니다.
- 실행 중인 SQLite DB를 공용폴더에 놓고 여러 PC가 직접 열지 마세요.
- 관리자 PC가 종료/절전되거나 프로그램이 종료되면 접속할 수 없습니다. 자동 실행은 포함하지 않았습니다.
- 사내망에서 TCP 8080 접속이 허용되어야 합니다. 정식 운영의 접속 범위와 HTTPS는 사내 IT 환경에 맞춰 설정합니다.

새 설치는 Windows x64/Python 3.12에서 `01_setup_windows.bat`로 자료실 의존성과 관리자 계정을 준비합니다. Python과 PaddleOCR 환경은 별도입니다. `offline-wheels-windows`는 자료실용 패키지이며 PaddleOCR용 패키지를 포함하지 않습니다.

## 검증 범위

기존에 제공된 실제 PaddleOCR JSON을 파싱해 강철의 함성, 금속노조 충남지부 현대제철지회, 2026-10-21, 26-29호 분류를 확인했습니다. 서버·파서·실패 보존·대기열·묶음 검토·게시·재시작 복구 테스트와 구문 검사를 진행했습니다. 모의 Paddle 모듈을 실제 하위 프로세스로 실행해 두 요청에 모델 생성이 한 번임을 확인했습니다. 개발 환경에서 실제 Windows PaddleOCR 추론은 실행하지 못했으므로 회사 PC에서 새 자료 한 장으로 연결을 확인하세요.

## 법령·규정 아카이브

상단 **법령·규정**에서 원문을 통합 검색하고, 검색창 아래 문서 종류 태그로 결과를 좁힐 수 있습니다. 검색 결과는 조문별 카드로 표시되며 전체보기를 눌러 원문을 확인합니다.

관리자는 **원문 등록**에서 문서 종류를 선택하고 원문을 붙여넣은 다음 **원문 분석**으로 조문과 확인 필요 항목을 살펴보고 저장합니다. 같은 종류를 다시 저장하면 현재 원문과 검색 색인이 함께 교체됩니다. 원문 내용과 시행일은 자동으로 만들어지거나 검증되지 않으므로 정확한 문서를 직접 확인하세요. 원문은 서버 PC의 `data/archive.db`에 저장됩니다. 현재 법령·규정 탭은 관리자와 팀원 화면 모두에서 비활성화되어 있습니다.

기존에 등록한 근로기준법·노동조합법·단체협약은 기존 화면에서 현재 문서로 쓰던 마지막 등록 원문을 이관합니다. 기존 취업규칙은 기술직·일반직 중 어느 것인지 자동으로 판단할 수 없어 **원문 등록**의 ‘자동으로 분류할 수 없는 기존 원문’에서 관리자가 직접 확인하여 선택해야 합니다. 시행령도 새 문서 종류에 포함되지 않아 해당 목록에 남습니다. 기존 판본 데이터는 삭제하지 않습니다.

## 동향 메모의 관련 조직

동향 메모의 관련 조직은 직접 입력할 수 있습니다. 여러 조직은 쉼표로 구분하거나 각각 입력하고 **태그 추가**를 누릅니다. 입력 후 바로 저장해도 태그로 등록됩니다. 메모 상단에는 현재 목록에서 가장 많이 사용된 태그 최대 10개가 표시되며, 그 밖의 조직은 검색창에서 찾을 수 있습니다.
